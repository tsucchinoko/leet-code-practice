# jump-game-2

## 問題要約

0-indexed の整数配列 nums（長さ n）が与えられる。最初はインデックス 0
にいる。各要素 nums[i] は、位置 i から前方に跳べる最大距離を表す。つまり、位置 i
にいるとき j を満たす任意の位置 i + j (0 <= j <= nums[i], i + j < n)
にジャンプできる。目的はインデックス
n-1（配列の最後）に到達するためのジャンプ回数を最小化すること。入力は必ず到達可能である。

例:

- 入力: nums = [2,3,1,1,4] → 出力: 2（0→1→4）
- 入力: nums = [2,3,0,1,4] → 出力: 2

## 制約

- 1 <= nums.length <= 10^4
- 0 <= nums[i] <= 1000
- 常に最後のインデックスに到達可能である（到達不能なケースは与えられない）

（時間・空間複雑度に関する実用的な目安）

- 目標は O(n) または O(n log n) 程度の時間で解くこと。単純な BFS
  的アプローチでも最悪 O(n^2) になり得るため、注意。

## 考え方

問題は「最小ジャンプ数」を求めるもので、幅優先探索（BFS）的なレイヤーを配列上で行う考えが有効。効率良く
O(n)
で解く代表的な戦略はグリーディ（貪欲）法で、現在のジャンプで到達可能な範囲（currentEnd）と、その範囲から次に到達可能な最遠位置（farthest）を追跡する方法：

1. currentEnd: 現在のジャンプ回数で到達できる右端（境界）。
2. farthest: currentEnd
   内のどこかの位置から、次にジャンプしたときに到達可能な最遠のインデックス。

アルゴリズム概要（1 回の配列走査で完了）:

- jumps = 0
- currentEnd = 0
- farthest = 0
- i を 0 から n-2
  まで走査（最後のインデックスまで到達する必要があるため、最後の要素は見ない）
- farthest = max(farthest, i + nums[i])
- もし i == currentEnd:
  - ここまでの範囲が尽きたので、ジャンプ回数を 1 増やし、currentEnd =
    farthest（次のジャンプで到達可能な範囲に更新）
  - （currentEnd が既に n-1 以上なら終了）
- 最終的に jumps が最小ジャンプ数

直感:

- 各ジャンプは「現在の到達可能区間」を一括で使い尽くすまでスキャンし、その区間内で最も遠くへ行ける候補を計算してからジャンプする（最適な次の跳躍先を局所的に決定）。これは局所最適が全体最適になるため有効。

正当性（簡単に）:

- 各ジャンプごとに区間内で最も遠く到達できる位置へ移ることは、残りの最小ジャンプ数を削減するための最善の選択肢を保持するため、グリーディに安全。

実装の注意点:

- nums.length が 1 の場合は 0 を返す（既に最後にいる）。
- ループを n-2 まで回すのは最後の要素へ到達するカウンタの更新を正しく行うため。
- farthest は i + nums[i] の最大を保持。currentEnd を更新した時点で jumps++。
- 配列要素が 0 でも到達可能性は保証されているのでガードは不要。
