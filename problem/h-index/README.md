# h-index

## 問題の性質

- グリーディ / カウント / ソートに関する問題。
- 配列の要素数 n は最大 5,000 と小〜中規模。ソート O(n log n) や線形スキャン
  O(n) が許容される。
- 結果は単一の整数（h-index）を返す決定問題的出力。

## 問題要約

研究者の論文ごとの被引用数を格納した整数配列 citations が与えられる。h-index
は「被引用数がそれぞれ少なくとも h 回である論文が h 本以上存在するような最大の h
値」である。配列を受け取り、h-index を返す。

例:

- 入力: citations = [3,0,6,1,5] → 出力: 3
- 入力: citations = [1,3,1] → 出力: 1

## 制約

- n == citations.length
- 1 <= n <= 5,000
- 0 <= citations[i] <= 1,000

（部分的に覚えておくと良い点）

- 被引用数の最大値は 1000
  と比較的限定的なので、カウントソート的な手法で線形時間にできる。
- n が小さいため、シンプルに降順ソートして走査する方法でも十分高速。

## 考え方

2つの代表的アプローチを簡潔に示す。

1. 降順ソートして走査（簡単で直感的）
   - citations を降順にソートする。
   - 0-based インデックス i に対して、要素が i+1 以上である限り h を増やせる。
   - 具体的には、ソート後に i を 0 から n-1 まで進め、もし citations[i] >= i+1
     なら h = i+1
     を更新。そうでないときループを抜ける（最大を求めるため全走査しても可）。
   - 計算量: O(n log n)、空間は入力コピーやインプレースで O(1)〜O(n)。

2. カウント（バケット）法 — O(n) 時間、追加 O(n) 空間
   - citations[i] の値が 0..1000 に制限されていることを利用。
   - バケット counts[0..n] を用意し、被引用数 x が n を超える場合は counts[n]
     に集約する（h-index は最大 n）。
   - 各論文をカウントしてから、最も被引用数の多い側から累積和を取り、累積数 >= k
     となる最小の k を求める。この k が h-index。
   - 計算量: O(n)、追加空間 O(n)。

問題の性質（まとめ）

- 計算量と実装の容易さを比べると、ソート法は簡潔で十分だが、最良の時間複雑度を求めるならカウント法を選ぶ。
