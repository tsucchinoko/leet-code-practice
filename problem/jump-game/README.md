# jump-game

## 問題要約

整数配列 nums
が与えられる。配列の最初のインデックス（0番）から開始し、配列の各要素 nums[i]
はその位置から最大で何歩ジャンプできるかを表す。最後のインデックス（nums.length -
1）に到達できるなら true、到達できなければ false を返す。

例:

- nums = [2,3,1,1,4] → true（0→1（1歩）、1→4（3歩））
- nums = [3,2,1,0,4] → false（どうやってもインデックス3で停止して先へ進めない）

## 制約

- 配列長: \(1 \leq \text{nums.length} \leq 10^{4}\)
- 各要素: \(0 \leq \text{nums[i]} \leq 10^{5}\)

これらは入力サイズ・値の上限を示す。線形〜準線形アルゴリズムが現実的。

## 考え方

目的は「先頭から最後尾へ到達可能か」を判定すること。代表的で効率的な考え方をいくつか挙げ、推奨する解法を解説する。

1. ブルートフォース（全探索・再帰／DFS）
   - 各位置から可能なジャンプ幅すべてを試す。最悪で指数時間になり、制約下では現実的でない。

2. 動的計画法（メモ化）
   - 各インデックスを「到達可能」「不可能」「未訪問」でメモしつつDFSを行うことで重複計算を避ける。最悪
     O(n^2) になる場合があり、n=10^4 のときやや重いが場合により可。

3. グリーディ（貪欲）法 — 推奨
   - 先頭から走査しながら、現在到達可能な最も遠い位置（maxReach）を維持する。
   - インデックス i を順に見ていき、もし i > maxReach
     ならそこまで到達できないため false を返す。
   - 各位置で maxReach を更新： maxReach = max(maxReach, i + nums[i])。
   - 最終的に maxReach >= lastIndex なら true。
   - 時間計算量 O(n)、追加メモリ O(1)。制約に最適。

直感的説明:

- 現在までに到達可能な最遠位置を追い、配列を左から右へ一回走査するだけ。途中でその最遠位置より先に進む必要が生じたら到達不可。

正当性の簡単な議論:

- ある時点で maxReach
  が更新されている限り、その範囲内にあるすべての選択は考慮済みと見なせる。i が
  maxReach
  を超えたとき、それより先の位置へはどのようなジャンプの組み合わせでも届かないため終了できる。

## 要点（簡潔に）

貪欲法（グリーディ法）は「局所的に最善と思える選択を逐次行うことで、最終的に大域的な最適解（あるいは問題の目的）を得ようとする設計戦略」です。問題に応じて「最大化・最小化・到達可能性・覆い尽くし」などの目的を満たすために、各段階で最も望ましい選択を行います。

## 詳細説明

### 1. 貪欲法の目的

貪欲法は次の何れか（あるいは複数）を求めるために使われます。 1.
問題の最適解（最小コスト、最大利益など）を高速に求めること。 2.
到達可能性や可否の判定（今回のジャンプ問題のように「最後に到達できるか」）を効率的に判定すること。
3.
覆い（カバリング）やスケジューリングなどで、十分良い（あるいは最適な）解を得ること。

### 2. 貪欲選択の特徴

    1. 局所性：各ステップで現在の状況に基づき「最善と思われる」選択を行う（過去の選択は基本的に変更しない）。
    2. 単純さ：多くの場合、状態を一つの尺度（例：現在到達可能な最遠位置、残り容量、現在の価値合計など）で表し、それを更新していく。
    3. 計算効率：通常は線形〜多項式時間で解け、メモリも少ない（O(1)〜O(n)）ことが多い。

### 3. 成功条件（貪欲法が有効になるとき）

貪欲法が最終的に正しい（最適または正当な）解を与えるには、問題が以下のような性質を持っている必要がある場合が多いです。

1. 貪欲選択性（Greedy-choice
   property）：局所での貪欲選択がグローバルな最適解の一部となる。 2.
   最適部分構造（Optimal
   substructure）：大域的最適解が部分問題の最適解から組み立てられる。
   これらが成立する場合、貪欲法は正当化でき、正解を返すことが保証される。

### 4. 例（カテゴリ別）

    1. 最小コイン問題（一般的な貨幣体系では貪欲は最適、ただし任意のコイン体系では必ずしも最適ではない）
    2. 活動選択問題（終了時間でソートして早く終わるものを選ぶ貪欲法は最適）
    3. Huffman 符号化（頻度の低いものを結合する貪欲な操作で最適な符号木を構成）
    4. ジャンプ問題（今回の例）では「現在到達可能な最遠位置」を貪欲に伸ばすことで到達可否を O(n) で判定でき、正当性は到達区間の連鎖的拡大という観点で説明できる。

### 5. 貪欲法が失敗する例（注意点）

貪欲法は万能ではなく、局所的に最良の選択が全体の最良にならない問題も多い。代表例：

1. 0/1
   ナップサック問題（重み付き価値の比率で貪欲選択すると最適にならないことがある）
2. 特殊なコイン体系での最小コイン数問題（貪欲が間違った組合せを選ぶ場合がある）
   したがって、貪欲法を使う前に問題の性質（貪欲選択性や最適部分構造の有無）を確認する必要がある。

### 6. 実用的な判断基準（使う／使わないの判断）

    1. 問題が「区間の覆い」「到達範囲の拡大」「逐次選択の重複がない」等の構造を持つなら貪欲が有力。
    2. 小さな局所選択が将来に影響を与えるが、その影響を局所的指標で適切に評価できるかを考える（例：今回なら i+nums[i] が評価指標）。
    3. 必要なら帰納法や交換論法（exchange argument）で貪欲選択の正当性を証明する。

## まとめ（今回のジャンプ問題における貪欲法）

今回の問題では「現在到達できる区間の右端（maxReach）を常に最大化する」ことが目的です。各位置で
i+nums[i] を見て maxReach
を更新する貪欲選択は、到達範囲を連鎖的に正しく拡げられるため、最終的に最後尾に到達できるかどうかを正しく判定できます。計算量は
O(n)、追加メモリは O(1) で効率的です。
