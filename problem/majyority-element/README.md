# majyority-element

## 問題要約

配列 nums（長さ n）が与えられる。多数（majority）要素を返せ。
多数要素とは、配列内で出現回数が ⌊n / 2⌋
を超える要素を指す。問題の前提として、必ず多数要素が存在するものとする。

例:

- 入力: nums = [3,2,3] → 出力: 3
- 入力: nums = [2,2,1,1,1,2,2] → 出力: 2

## 制約

- n == nums.length
- 1 <= n <= 50,000
- -10^9 <= nums[i] <= 10^9
- 多数要素は必ず存在する（返却値は必ず決まる）

追加の問い（Follow-up）: 時間計算量 O(n)、補助空間 O(1) で解けるか。

## 考え方

1. ブルートフォース（非効率な考え方）
   - 各要素についてカウントし、最大出現要素を返す。ハッシュマップを使えば O(n)
     時間、O(n) 空間。
   - 制約下では十分だが、補助空間が O(n) となる。

2. ソートを使う方法
   - 配列をソートすると、多数要素は中央位置（index
     ⌊n/2⌋）に必ず来るため、ソート後の中央要素を返す。時間 O(n log
     n)、空間はソート実装次第（一般に O(1) または O(n)）。
   - 制約は満たすが最適ではない（時間は線形でない）。

3. ボイヤー＝ムーアの多数決アルゴリズム（最適解）
   - 目的: O(n) 時間、O(1) 空間を達成する。
   - 考え方:
     - 候補 candidate とカウント count を用意する（初期は任意）。
     - 配列を先頭から順に走査する。
     - 現在の要素 x を見るとき:
       - count が 0 のとき candidate を x に設定し count = 1 とする。
       - そうでなければ、もし x == candidate なら count++、異なれば count--。
     - スキャン終了時の candidate
       が必ず多数要素になる（多数要素が存在する前提の下）。
   - なぜ成り立つか（直感）:
     - 多数要素は配列の要素のうち半分を超えるため、異なる要素との「相殺」（candidate
       と異なる要素が出るたび count を減らす）をしても最終的に残る。
   - 注意:
     - 問題の前提で多数要素が常に存在するため、最終 candidate
       を返せば良い。一般に存在が保証されない場合は、最後に candidate
       が本当に多数かを再カウントして検証する必要がある。

4. 実装上のポイント（Go）
   - candidate と count をそれぞれ int 型で持つ。nums の全体を一度走査するだけ。
   - count を 0 に初期化し、最初に来た要素を candidate
     にするやり方で簡潔に書ける。
   - テストは複数ケースを含める（例に挙げられているものや単一要素、最長のケース近くのものなど）。
