## 問題の性質

- 循環（円環）上に並ぶガソリンスタンドを1周できるかを判定する巡回路問題。
- 各駅で得られる燃料と次駅までに消費する燃料が与えられ、空のタンクから出発できるかを問う。
- 解が存在する場合は一意である（問題設定による保証）。

## 問題要約

- 入力: 長さ n の整数配列 gas と cost（n は 1 以上 10^5 以下、各要素は
  0〜10^4）。
- 意味: i 番目のスタンドで gas[i] のガソリンを補給、i から (i+1) mod n
  への移動に cost[i] を使う。
- 初期のタンク量は
  0。ある開始インデックスから時計回りに1周できるならそのインデックスを返す。できないなら
  -1 を返す。
- 解が存在する場合は一つだけ（ユニーク）。

## 制約

- n == gas.length == cost.length
- 1 <= n <= 100,000
- 0 <= gas[i], cost[i] <= 10,000
- 答えが存在するなら一意

（計算量とメモリの観点）

- 時間計算量は O(n) を目指す。二重ループなどの O(n^2) は n = 10^5 では不適。
- 追加メモリは O(1) が望ましい（入力以外に大きな配列を作らない）。

## 考え方

基本的かつ効率的なアルゴリズム（貪欲法）を説明します。

1. 総和チェック（必要条件）
   - 全体で得られるガソリンの合計が消費合計未満なら、どこから始めても1周不可能 →
     すぐ -1 を返す。
   - 数式でいうと \(\sum_i (gas[i] - cost[i]) < 0\) なら不可能。

2. 開始位置決定（貪欲に更新）
   - ある開始位置 start を仮定して走らせ、途中でタンクが負になる最初の地点 j
     を見つけたとする。このとき start..j のどの位置を開始としても j
     には到達できない（部分的に証明可能）。したがって start を j+1
     に移して再試行して良い。
   - これを配列一周分（各インデックスを一度だけ）行えば、O(n)
     時間で開始インデックスを見つけられる。
   - 実装上は単に走査しながら現時点での累積 surplus を維持し、もし負になれば
     start = i+1 にし surplus を 0 にリセットする。
   - 最後に総和チェックで可能であれば start が解（ユニーク）になる。

直感：

- どの区間で途中で破綻（ガス不足）したかを検出したら、その区間のどの点から始めても破綻するため、次の位置から再開すればよい。全体合計が非負なら最終的に見つかる開始点は一意。

時間・空間：

- 時間 O(n)、追加空間 O(1)。

## キーワード

- 貪欲法（Greedy）
- 累積和（Prefix sum）
- 円環（Circular array）
- 1周判定、開始位置探索
- O(n) アルゴリズム
